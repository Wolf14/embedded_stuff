Learning:
    1] What is the setup process:
        Step 1 - openocd: 
            Loads interface config
                ST-Link
                SWD protocol
            Loads target config
                STM32F4
                Cortex-M4
            Initializes:
                Debug Access Port (DAP)
                Memory access
                Flash driver
                Halts or resets the core (depending on config)
            At this point OpenOCD has direct control of the MCU, it can: Read/write memory, Halt/resume CPU, Program Flash, Read registers
            But: It has no idea about your source code, No symbols, No main()
        Step 2 — OpenOCD becomes a server
            OpenOCD then opens TCP ports:
            Port	Purpose
            3333	GDB server
            4444	Telnet console
            6666	TCL interface
            OpenOCD is now saying: “If anyone speaks GDB Remote Protocol on port 3333, I’ll translate it to hardware operations.”
        Step 3 — What happens when you start arm-none-eabi-gdb
        You run:
            GDB:
                Loads: the ELF file 
                Reads: Symbols, Sections, Debug info
                Knows: Where Reset_Handler is, Where main is, What variables exist
            But: GDB has no hardware access, It cannot touch the MCU yet
        Step 4 — "target remote :3333"
            This is the handshake. GDB connects to OpenOCD over TCP. They speak GDB Remote Serial Protocol
            GDB says things like: “Read register R0”, “Set breakpoint at 0x08000008”
            OpenOCD translates that into: SWD/JTAG operations, Register reads, Flash patches
            Now: GDB controls execution, OpenOCD controls hardware
        Step 5: what happens when you type continue?
            GDB: Sends continue command to OpenOCD
            OpenOCD: Releases the CPU, Core starts executing from PC
            If the program: Hits a breakpoint → OpenOCD halts CPU → GDB regains control | Crashes → CPU faults → OpenOCD reports halt
        Step 6 — Why OpenOCD needs board config (st_nucleo_f4.cfg)
        That file tells OpenOCD:, Which probe to use (ST-Link), Which transport (SWD), Which MCU (STM32F4), Which Flash driver, Clock speed, Reset behavior
        Without it: OpenOCD doesn’t know how to talk to your board


    2] Reset -> main()
    ResetHandler:   tiny piece of code that runs 1st when a microcontroller resets
                    - is the entry point of your program after a reset event.
                ensures:
                    - Stack pointer(SP) is set correctly
                    - the .data section(initialized variables) is copied from Flash to RAM
                    - The .bss section (zero initialized variables) is cleared
                    - The system clockand other basic configurations are initialized
                    - Finally the main() funciton is called
                Reset Handler executes after any reset event:
                    Power-On Reset (POR)
                    Manual Reset (reset button)
                    Watchdog Reset
                    Brown-Out Reset
                    Software Reset
    By default, the Vector Table is located at address 0x00000000, typically mapped to Flash. Immediately after reset, the Cortex-M core looks for one thing that is Vector Table
    After a reset (power-on, software, or external), the Cortex-M processor begins execution at address 0x00000000, in Thread mode using the Main Stack Pointer (MSP) by default
        -> Depending on the configuration, thread mode can operate in privileged or unprivileged mode.
    Entry 0 (0x00000000): Initial MSP Value
        The first entry in this table is the initial stack pointer. The core initializes the Main Stack Pointer: MSP ← *(0x00000000).
    Entry 1 (Address 0x0000 0004): Reset Handler Address
        Second entry of the Vector table is the reset handler address. The core loads the address of the first instruction it must execute: PC ← *(0x00000004)
    
    Linker always refers to physical memory addresses.
    Possible reason for VTOR?:
    The vector table can be placed in read-only memory or RAM. Placing it in ROM saves RAM space while locating it in RAM allows dynamic updating of vector addresses

    Step by step reset sequence:
        Reset Triggered: Cortex-M processor begins execution at address 0x00000000, in Thread mode using the Main Stack Pointer (MSP) by default. Depending on the configuration, thread mode can operate in privileged or unprivileged mode.
        Stack Pointer Initialization: The processor reads the initial stack pointer value from address 0x00000000 and loads it into the SP (Stack Pointer) register.
        Program Counter Initialization: the processor reads the reset vector from address 0x00000004, which contains the address of the Reset_Handler. This value is loaded into the Program Counter (PC).
        Jump to Reset_Handler:
        Call to SystemInit():
            Reset_Handler first calls the SystemInit() function, which typically performs:
            Clock configuration (e.g., PLL, XTAL, HSE/HSI setup)
            FPU (Floating Point Unit) settings (if available)
            Vector table base address setup (via VTOR)
            Memory system initialization
        Jump to __main:
            After SystemInit(), the control is transferred to __main, a function provided by the toolchain’s runtime. This is not the same as your application’s main() function.
            __main is responsible for:
                Initializing the C runtime environment
                Copying initialized data from ROM to RAM,
                Zero-initializing the .bss section,.
                Invoking C++ global constructors (if any).
                Finally calling the user-defined main() function
                Call the main function

STM32 Cortex M4 specific:(from programming manual)
    - The processor uses a full descending stack
    - The processor implements two stacks, the main stack(MSP) and the process stack(PSP), with independent copies of the stack pointer
    - In Thread mode, the CONTROL register controls whether the processor uses the main stack or the process stack
    - The VTOR register is a 32-bit writeable CPU register present in all Cortex-M variants
    - On reset, the processor loads the VTOR with the fixed vector table base address which is 0x00000000 for Cortex-M0/M0+ 
    and 0x00000004 for Cortex-M3/M4. This maps the vector table to the start of the code memory region.

GPIO PIN Configuration:
    - GPIOx_MODER (x = A..H):
        These bits are written by software to configure the I/O direction mode.
            00: Input (reset state)
            01: General purpose output mode
            10: Alternate function mode
            11: Analog mode
    - GPIOx_OTYPER
        Bits 31:16 Reserved, must be kept at reset value.
        Bits 15:0 OTy: Port x configuration bits (y = 0..15)
        These bits are written by software to configure the output type of the I/O port.
            0: Output push-pull (reset state)
            1: Output open-drain

        Push Pull:
            Push-pull output uses a pair of transistors to actively drive the pin both high and low. When output high-> Upper transistor pulls output towards VCC actively
             On a low output the lower transistor pulls the output low actively while the high side blocks.
            Push/Pull is faster as both paths to HIGH and LOW are low Impedance and is normally what you go for by default
        Open-Drain:
            uses a single N-MOS that pulls the line to ground when active; when inactive the output is left floating
            Open-drain depends on a pullup resistor to provide the high state while the low state is actively created by a transistor. 
            So the pullup network has relatively high impedance to VDD and very low impedance to GND because when the transistor fully turns on, it is effectively a short to GND.
            Impedance in a graphical sense is how fast teh voltage level changes to the setpoint(HIGH or LOW, higher impedance implies slower transition, so Open Drain reaches Ground Voltage very fast,(higher slope, but vice versa is slow))
            When the MOSFET is HIGH, the Impedance to Ground is LOW pulling it to low adn allowing higher currents to flow. When the MOSFET Gate is Open, the impedance is higher leaving the state of the drain as floating.
            A pull up resistor is required to set the Drain state to High in the High impedance state of the MOSFET
            -These tend to be used when more than 1 device is connected on a bus like I2C


    - GPIOx_OSPEEDR
        These bits are written by software to configure the I/O speed.
            00: Low speed
            01: Medium speed
            10: Fast speed
            11: High speed
    - GPIOx_PUPDR
        These bits are written by software to configure the I/O pull-up or pull-down
        PUPDR controls internal resistors that weakly pull a GPIO pin to HIGH or LOW when nothing else is driving it.
            Yes → it is mainly relevant for input pins
            It prevents the pin from floating, It does not drive the pin like an output
            A GPIO input pin is high-impedance.
            That means:
                It does not force 0 or 1
                If nothing is connected → the voltage is undefined
                The pin can randomly read 0 or 1 due to noise
            This is called a floating input.
            Inside the STM32, each pin has two weak resistors connected to it:
                                  3.3V
                                    |
                                 [ Pull-up ]
                                    |
                                   PIN
                                    |
                                 [ Pull-down ]
                                    |
                                   GND
            Very important to set PUPDR when using in INPUT Mode
            If pin is output: Output driver forces voltage, Pull-up/down has little effect
            
            00: No pull-up, pull-down
            01: Pull-up
            10: Pull-down
            11: Reserved
    - GPIOx_IDR
        Bits 31:16 Reserved, must be kept at reset value.
        Bits 15:0 IDRy: Port input data (y = 0..15)
            These bits are read-only and can be accessed in word mode only. They contain the input value of the corresponding I/O port.
    - GPIOx_ODR
        Bits 31:16 Reserved, must be kept at reset value.
        Bits 15:0 ODRy: Port output data (y = 0..15)
            These bits can be read and written by software.
        Note: For atomic bit set/reset, the ODR bits can be individually set and reset by writing to the GPIOx_BSRR register (x = A..H).
    - GPIOx_BSRR
        Bits 31:16 BRy: Port x reset bit y (y = 0..15)
        These bits are write-only and can be accessed in word, half-word or byte mode. A read to these bits returns the value 0x0000.
            0: No action on the corresponding ODRx bit
            1: Resets the corresponding ODRx bit
        Note: If both BSx and BRx are set, BSx has priority.
        Bits 15:0 BSy: Port x set bit y (y= 0..15)
        These bits are write-only and can be accessed in word, half-word or byte mode. A read to these bits returns the value 0x0000.
            0: No action on the corresponding ODRx bit
            1: Sets the corresponding ODRx bit
    - GPIOx_LCKR
        Bits 31:17 Reserved, must be kept at reset value
        Bit 16 LCKK[16]: Lock key. This bit can be read any time. It can only be modified using the lock key write sequence.
        Toggle the key in a precise pattern
            1️⃣ Prepare the lock mask
                You choose which pins to lock by writing LCK[15:0].
            2️⃣ Toggle the key in a precise pattern
                The hardware watches for:
                1 → 0 → 1
            3️⃣ If and only if the pattern is correct:
                Lock engages
                LCKK becomes permanently 1
                LCK[15:0] become read-only
            4️⃣ Any mistake → lock aborted
        Bits 15:0 LCKy: Port x lock bit y (y= 0..15)
            These bits are read/write but can only be written when the LCKK bit is ‘0. 0: Port configuration not locked 1: Port configuration locked
        No software unlock exists. Resets only in the case of system reset
    - GPIOx_AFRL
        Controls Alternate functionality of pins 0-7
        Each pin has 4 bits. hus 8 * 4 = 32 bits. Hence 2 registers exist
    - GPIOx_AFRH
        Controls Alternate functionality of pins 8-15

USER BUTTON PC13:
User button on Nucleo F446RE, Button B1 is connected to PC13 (GPIO Port C, pin 13)
Connected like:     +3.3V ---[Button]--- PC13 --- GND (via internal pull-up)
Electrical behavior:
    Not pressed: PC13 is high (logic 1)
    Pressed: PC13 is pulled low (logic 0)

Optionally enable pull-up (in PUPDR register) to ensure stable high when button is unpressed:
Why PC13 needs pull-up specifically? 
Your button wiring:    PC13 ---- BUTTON ---- GND
Pressed → forced LOW, Released → nothing drives it
So you must pull it HIGH when released → pull-up.

IMPORTANT: A button must connect the pin to the opposite rail of the pull resistor when pressed.
Case 1: Default-> HIGH
                3.3V
                 |
                [ Pull-up ]
                 |
                 PIN ---- BUTTON ---- GND

Case 2: Default -> LOW
                GND
                 |
                [ Pull-down ]
                 |
                 PIN ---- BUTTON ---- 3.3V

On the Nucleo F446RE: There is an external pull-up resistor on PC13


Questions:
- What is a Reset Event?
    - reset event in a microcontroller forces it to stop its current operation and return to a known, initial state, like when it first gets power, by clearing registers, reinitializing peripherals, and restarting program execution from the beginning
    - Its address is stored in the Vector Table, which resides at the start of the Flash memory
        For ARM Cortex-M microcontrollers:
            -> The first entry in the vector table: Initial Stack Pointer value
            -> The second entry: Address of the Reset Handler.
    - Reset Handler executes
        Initialize .data and .bss sections in RAM.
        Optionally configure the system clock and peripherals.
        Call SystemInit() (common in CMSIS-based systems).
        Call __libc_init_array() (for C++ constructors).
        Finally, call main().
    - A microcontroller reset circuit is a circuit designed to ensure that a microcontroller (microcontroller) will function properly at startup or under abnormal conditions. The main function of a reset circuit is to restore the internal state and registers of the microcontroller to a known initial state so that program execution can begin
    - RESET CIRCUIT: The reset circuit usually consists of a resistor, capacitor and/or voltage regulator used to generate an appropriate reset pulse signal. This signal is passed to the reset pin of the microcontroller to trigger a reset operation.
    - Reset Vector: During a reset, the microcontroller jumps to a specific reset vector address from where it starts executing the initialization routine. This vector address is usually fixed and determined by the manufacturer of the microcontroller.
- Difference b/w Flash and RAM?
    - Two types of RAM are commonly used in a computer system: dynamic RAM (DRAM) and static RAM (SRAM). 
    - In addition to being the fastest option, SRAM is much more expensive than DRAM, so it is mainly used as the cache memory inside the integrated circuit that is a computer's CPU
    - DRAM is mainly used as the primary operational memory, running the OS and applications.
    - Less expensive still is flash memory. Flash memory is non-volatile and can hold data even without power, unlike RAM. Compared to either type of RAM, flash memory speed is significantly slower
- What is Stack pointer?
    - usually maintained as a LIFO data structure 
    - The stack pointer is initialized only one time in the program.
    - stack incrments when you PULL an item OFF the stack and decrements when u PUSH an item ON the stack
- What is a Program Counter?
    - a special CPU register that holds the memory address of the next instruction to be executed
- What is VTOR(Vector Table Offset Register)?
    - crucial system control register in most ARM Cortex-M processors that specifies the memory address where the processor should look for the start of the vector table
    - VTOR's primary function is to allow developers to relocate this table from its default memory location (typically the start of flash memory, address 0x00000000) to another location, often in SRAM (RAM). 
- Why 0x08000000 instead of 0x00000000 in linker.ld?
    - ARM mandates that the CPU fetches the reset vector from address 0x00000000.
        -ARM Cortex-M specification says:
            On reset:
                Load MSP from address 0x00000000
                Load PC from address 0x00000004
            It does NOT mandate where Flash physically lives.
    - STM32 aliases Flash at 0x08000000 to 0x00000000 at reset.
    -Your linker script:
        FLASH (rx) : ORIGIN = 0x08000000, LENGTH = 512K
        SRAM  (rwx): ORIGIN = 0x20000000, LENGTH = 128K
    This is not describing CPU reset behavior. It is describing: “Where should the linker place sections in the physical memory map of this MCU?”
    This memory map comes from STM32’s silicon design, not ARM.
    STM32F4 uses boot time aliasing at reset: 0x00000000 → alias of selected boot memory, So:
        CPU reads 0x00000000, but Hardware routes that read to Flash at 0x08000000
- Where exactly does the aliasing happen?
    Inside STM32 silicon:
        - AHB bus matrix
        - Address decoder
        - Boot configuration logic
    Proof:
        try:     x/8x 0x00000000 and x/8x 0x08000000    these both return the same values
-Why does "info registers" return the register values even if I havent defined them in code/linker/startup?
    The command reads the CPU’s architectural registers directly via the debug hardware.
    You don’t need to define them. They exist because the Cortex-M core exists.
    They are physically implemented inside the Cortex-M4 core.
    The ARM architecture mandates these registers:
        Core registers (always present)
        Register	Purpose
        r0–r12	General-purpose
        sp (r13)	Stack pointer
        lr (r14)	Link register
        pc (r15)	Program counter
        xPSR	Program status
        MSP / PSP	Stack pointers
        CONTROL	Privilege / stack select
        PRIMASK / BASEPRI	Interrupt masking
    These exist even if flash is empty.

- Why is FLASH only 512Kb when the boundary mentioend in manual is "0x08000000 - 0x081F FFFF" which amounts to 2097151 Bytes
    The STM32 reference manual shows the maximum possible flash address space for the entire family, not what your specific chip has populated.
    So that region represents up to 2 MB of flash, because some STM32F4 parts actually have 1 MB or 2 MB flash.
    If you access beyond 512Kb, Reads may return 0xFFFF_FFFF, Writes will fault or be ignored, Execution will likely HardFault
    Why ST does this (design reason), ST uses:
        One common Cortex-M memory map
        One linker model
        One reference manual
